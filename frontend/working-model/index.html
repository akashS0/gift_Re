01 · The models

Four ways to ask the same question

Every quarter, for each of the 1,000 largest NSE companies, the question is the same: will this stock be among the top 100 performers next quarter? We give each model the same 13 factor parameters (X1–X13) and compare how they answer. Two are classical statistics; two are deep learning. The differences are in what patterns they can see.

Logistic regression
Baseline · linear

Assigns one weight to each factor, adds them up and squashes the total through a sigmoid into a probability. Value, quality, momentum and alpha each push the score up or down by a fixed amount, regardless of what the other factors are doing.

StrengthTransparent — every weight is a number an actuary can audit.
LimitCannot see interactions (cheap and improving momentum) or regime changes.
Role at Gift Re: the explainability benchmark every other model must beat.
Random forest
Ensemble · non-linear

Grows hundreds of decision trees, each trained on a random sample of stocks and a random subset of the 13 factors, then averages their votes. A tree splits the universe step by step ("if value is high, then check momentum"), so it naturally captures interactions and thresholds.

StrengthNon-linear, robust to noise and outliers, gives factor-importance scores.
LimitTreats each quarter as a snapshot — no memory of how a stock got here.
Role at Gift Re: the model interviewees said IRDAI would accept most readily; also the source of feature-importance reporting.
Convolutional neural network (CNN)
Deep learning · pattern filters

Slides small learned filters across the factor history of each stock, the way image models slide filters across pixels. Each filter fires when it sees a particular local shape — a two-quarter momentum build, a quality dip followed by recovery. Pooling keeps the strongest signals; a final layer turns them into a probability.

StrengthFinds short, local patterns across factors automatically; fast to train.
LimitFilters have a fixed reach — long-range dependencies are hard to capture.
Role at Gift Re: the pattern-detector benchmark for deep learning; useful as an ensemble member.
Bidirectional LSTM (BiLSTM)
Deep learning · sequence memory · selected model

Reads each stock's factor history as a sequence, once forwards and once backwards, carrying a memory that its gates update at every quarter — keeping what matters, forgetting what is stale. This is why it can rotate between momentum, quality and value as regimes change, and why it down-weights old patterns when new data deviates sharply.

StrengthLong-range temporal dependencies; regime awareness; best backtest (43.3% CAGR, Sharpe 1.07).
LimitLeast transparent; needs dropout and hold-out discipline to avoid overfitting; slower to train.
Role at Gift Re: the production engine for the Top-30 float portfolio, wrapped in human investment-committee override.

02 · Process walkthrough

From 20 years of NSE data to a 30-stock portfolio

The pipeline is deliberately simple to audit. Data is labelled the same way for every model, the train/test split is fixed in time, and nothing from the test years touches training.

1
Universe and data

Top 1,000 NSE companies by market capitalisation. For each stock and each quarter, 13 factor parameters (X1–X13) drawn from the Nifty 200 factor families — Value, Quality, Momentum and Alpha — plus price and volume history. 20 years in total.

Source today: investment-team extract. Later: API / screener scraping.
2
Labelling — what "success" means

For every quarter, stocks are ranked by their next-quarter return. The top 100 of 1,000 are labelled 1, the rest 0. Every model therefore solves the same binary question, and outputs can be compared on the same metrics.

Only 10% positives — so accuracy alone is misleading (see Outputs).
3
60-day lag — no look-ahead

Fundamentals are only used 60 days after the quarter-end they describe, matching when results are actually published. This removes look-ahead bias: the model never sees numbers the market did not yet know.

4
Train 16 years, test 4 — in time order

Training data runs to 2021, including the 2008 GFC and the 2020 COVID crash so models see crisis signatures. The final four years (Q4 FY21–Q3 FY25) are held out entirely: no feature selection, tuning or early stopping uses them.

5
Preprocessing and regularisation

Factors are standardised cross-sectionally within each quarter, so a "high value score" always means high relative to peers that quarter. Deep models use dropout between layers and a small, theory-grounded feature set to limit spurious pattern-finding. Class imbalance is handled with positive-class weighting.

6
Train the four models

Logistic regression and random forest see each stock-quarter as a snapshot of 13 numbers. CNN and BiLSTM see each stock as a sequence of recent quarters (13 × L). All output a probability of being top-100 next quarter.

7
Selection funnel 1000 → 100 → 30

Each quarter the model ranks all 1,000 stocks and shortlists the top 100 by probability. The investment manager then applies fundamental analysis to pick 30. Stock weights are set by risk-return optimisation on the Sharpe (or Treynor) ratio. The portfolio is rebalanced quarterly.

8
Evaluate two ways

As a classifier: accuracy, AUC-ROC, precision, recall, F1 on the held-out years. As a portfolio: CAGR, standard deviation, beta, tracking error, Sharpe, Treynor, Jensen's alpha and information ratio versus the Nifty 50 and the Nifty 200 factor indices, at a 6.5% risk-free rate.

Guarding against overfitting
Strict hold-out. All reported returns come from 4 years the model never saw.
No train/test divergence. Training-period and test-period returns stay in a comparable range.
Multiple regimes. The test window spans the 2021 rally, 2022 tightening, 2023 mid-cap rally and 2024 election volatility.
Regularisation. Dropout between recurrent layers; only theory-grounded factor inputs.
Interpretable behaviour. The portfolio rotates between factors in line with asset-pricing theory.

Why accuracy misleads here. With 100 positives in 1,000, a model that says "no" to everyone scores 90% accuracy and finds nothing. Precision on the shortlist is the metric that matters for a 1000 → 100 → 30 funnel: a 40% hit rate on 100 names gives the investment manager ~40 genuine winners to choose 30 from. Evaluation therefore reports precision@100 and AUC, not accuracy.

Interfaces for the next phase

What the investment-team file must look like, what a trained model artifact must look like, and where the API / scraping feed will plug in later.

Quarterly data file
ColumnMeaning

History of at least 4 labelled quarters is needed for browser training; 8+ is better. Sequence models need each symbol present in consecutive quarters.
Trained model artifacts
  • models/logistic.json — {"features":[...], "mean":[...], "std":[...], "weights":[...], "bias":0.0}
  • models/rf.json — {"features":[...], "trees":[{ "f":0, "t":0.12, "l":{…}, "r":{…} } | {"v":0.3}]} (nested nodes; leaves carry v)
  • models/cnn/model.json and models/bilstm/model.json — TensorFlow.js Layers format exported from Keras with tensorflowjs_converter; input shape [seqLen, nFeatures], sigmoid output, plus a sibling norm.json with feature order, mean and std.
When an artifact is present the page uses it and marks the source as "artifact" in the validation table; browser training is the fallback.
Roadmap for the feed
  1. Now: manual upload of the investment-team extract each quarter (this page).
  2. Next: a scheduled job pulls factor data from a screener / market-data API into the same CSV layout and drops it in data/latest.csv; the page auto-loads it.
  3. Then: the Python models run server-side on the same schedule and publish models/* artifacts and a scored data/shortlist.csv; this page becomes the review console for the investment committee.
Governance hooks
  • Every run logs data hash, model versions, settings and the shortlist — the audit trail interviewees asked for.
  • Human-in-the-loop by design: the model stops at 100; the manager chooses 30.
  • Surrogate explanation: logistic weights and forest feature importances are reported next to BiLSTM picks so an Appointed Actuary can see which factors drove the quarter.
  • Drift check: precision@100 on each new labelled quarter is appended to a running series; retraining is triggered when it falls below the agreed floor.
